# 位置合わせと精度のはなし

「この画像は、なぜ地図の正しい場所に乗るのか」
「乗った位置は、どれくらい信用していいのか」を説明する。

---

## 1. 画像そのものには「場所」の情報がない

写真は、ただの色の格子である。左上から何番目の画素が何色か、それだけしか入っていない。
これを地図に乗せるには、**外から**次の情報を与える必要がある。

1. 左上の画素が、地球上のどこにあるか
2. 画素1つが地上で何メートルぶんか
3. 北がどちらか（回転しているか）

この3つを **ジオリファレンス情報** という。今回のオルソでは、
`siteA_ortho.jgw` という6行のテキストファイル（ワールドファイル）に入っている。

```
0.1000000000        ← 画素の幅 10cm
0.0000000000        ← 回転（なし）
0.0000000000        ← 回転（なし）
-0.1000000000       ← 画素の高さ 10cm（下向きなのでマイナス）
15040.0500000000    ← 左上画素の中心の X
-204534.0500000000  ← 左上画素の中心の Y
```

GeoTIFF の場合は同じ情報が画像ファイルの中のタグに入っている。

つまり **「1画素＝10cm、左上はここ、回転なし」** という、それだけの取り決めで
画像が地面に貼り付けられている。難しいことは何もしていない。

---

## 2. その X, Y は何の座標か

`15040.05, -204534.05` は緯度経度ではない。
**平面直角座標系 XI（11）系**という、北海道南部用の「平らな紙の上の座標」である。

- 原点は **北緯44度・東経140度15分**（森町の北西、日本海上）
- そこから **東へ何メートル、北へ何メートル** かをそのまま数字にしたもの
- 森町は原点より南なので、Y（北距）がマイナスになる

なぜ緯度経度を使わないかというと、緯度経度は「角度」なので、
そのままでは距離や面積の計算ができないから。測量や林務の実務では、
メートルで扱えるこの座標系が標準になっている。

---

## 3. 画面に出るまでの変換

ビューアーは、次の順で変換している。

```
オルソの画素 (列, 行)
      ↓  ワールドファイル（掛け算と足し算だけ）
平面直角座標系XI系 (X, Y) メートル
      ↓  Krüger級数（投影の逆計算）
緯度経度 (lon, lat)
      ↓  Webメルカトル（地図タイルの決まり）
画面上の位置
```

**この3段階の計算で生じる誤差は、ミリメートル未満**である。
実際に、引き継ぎ資料に載っていた実測値と突き合わせて **誤差7cm以内**
（資料側が小数6桁までしか書いていないため、それ以上は追えない）であることを確認している。

```
py -3 tools/geo.py     ← この検算がその場で走る
```

つまり **ソフトウェアは誤差をほとんど足していない。**
ずれがあるとすれば、それは元のジオリファレンス情報がずれているということ。

---

## 4. 「精度」には2種類ある

ここがいちばん大事なところ。

### 相対精度 — オルソの中での正確さ

「この木とあの木は何メートル離れているか」「この林分は何ヘクタールか」

**これは正確。** 数センチ〜数十センチの世界。
なぜなら、オルソは何百枚もの写真を重ね合わせて、
画像同士の特徴点がぴったり合うように内部を組み立てているから。
内部の形はしっかりしている。

### 絶対精度 — 地球上のどこにあるか

「この木の緯度経度はいくつか」

**これは ±3〜5m ずれる。**

理由：ドローンに載っているのは普通のGPSで、自分の位置を±数メートルでしか知らない。
オルソは「正確に組み立てた立体模型」を、その**あいまいなGPSの値で地面に置いている**。

### たとえるなら

> 精密に印刷された地図を、机の上に **少しずらして** 置いた状態。
>
> - 地図の中で長さを測る → **正しい**
> - 地図の上の点が机のどこにあるか → **数センチずれている**
> - しかも、**全体が同じ方向に同じだけ**ずれている（バラバラにずれるのではない）

だから、森林簿と重ねると **全体が数メートル平行移動して見える**。
一部だけ合って一部だけずれる、という壊れ方はしない。

### 実際に測ってみた（2026-09-07）

上の「±3〜5m」は一般論なので、いま入っているオルソが実際どれだけずれているかを
測った。国土地理院の「シームレス空中写真」（全国の空中写真を国の基準点に合わせて
並べたもの）とオルソを重ね、模様が一番よく合う位置のずれを求めた。
z18（1画素 0.44m）のタイルを 4×4 枚つないだ約450m四方の窓を、
サイトごとに最大14か所とって中央値をとっている。

| サイト | 東方向 | 北方向 | ずれの大きさ | 判定に使えた窓 |
|---|---|---|---|---|
| Site F | +0.3 m | −0.6 m | **約 0.6 m** | 11 |
| Site G | +0.6 m | −0.5 m | **約 0.8 m** | 6 |
| Site H | −3.6 m | +0.1 m | **約 3.6 m** | 7 |
| Site B | +3.4 m | −6.0 m | **約 7 m** | 8 |
| Site A / C / D / E | — | — | **測れなかった** | 0〜2 |

- 符号は「オルソをこの向きに動かすと空中写真に合う」という意味。
  Site B なら、**オルソがいま 3.4m 西・6.0m 北にずれて描かれている**。
- A / C / D / E が測れないのは、一面の森林で照合できる模様が無いため。
  ずれが無いという意味ではない。
- 比べた相手（シームレス空中写真）自体にも数メートルの誤差と撮影時期の差があるので、
  この表の数字にも ±2m 程度の幅がある。

**わかること**

1. サイトによって絶対位置の質がかなり違う。Site F・G はほぼぴったり、Site B は 7m ずれている。
2. 同じサイトの中ではずれの向きと量がそろっている（Site B は8か所すべて東+2.3〜3.9m／北−5.8〜−7.1m）。
   平行移動のずれであって、歪んでいるわけではない、という上の説明どおりの結果。
3. **オルソを見ながら決めた木の位置には、そのサイトのずれがそのまま乗る。**
   Site B の範囲でオルソ上から特定した木の緯度経度は、真の位置から 7m ほど離れている可能性がある。
   現地で GPS を持って探す分には問題ない距離だが、
   数字だけを他所へ渡すときはこの幅を添えること。

測り直す手順は `docs/引き継ぎ.md` を参照。
新しいオルソを入れたら、同じやり方で確かめておくとよい。

## 5. 何に使えて、何に使えないか

| 用途 | 使えるか |
|---|---|
| 枯れている木がどのあたりにあるか把握する | **使える** |
| 木と木の間隔、林分の面積を測る | **使える** |
| 去年と今年で被害がどう広がったか見る | **使える**（同じ条件なら比較できる） |
| 現地で「この木だ」と特定する | **使える**（±5mなら現場では十分見つかる） |
| 林班・小班のどこかを判断する | **おおむね使える**（境界ぎわは注意） |
| **境界確定・地図訂正・図面作成** | **使えない** |
| **面積を根拠に補助金や契約の数字を出す** | **使えない** |

## 6. 相手側（森林簿）の精度も忘れない

重ねる相手にも誤差がある。北海道の森林計画関係資料には、こう明記されている。

> 実測によるものではなく、地域森林計画樹立のため**間接調査法により作成**したもので、
> 所有権等土地に関する諸権利、所有界、面積及び木竹の評価等を証明するものではありません。

つまり **小班の線も「だいたいここ」** である。
オルソと森林簿がずれて見えたとき、**どちらがずれているとも言い切れない。**
両方に数メートルの幅があると思って使うのが正しい。

## 7. どうすれば絶対精度を上げられるか

| 方法 | 精度 | 手間 |
|---|---|---|
| **対空標識（GCP）を置く** … 地上に目印を置き、その正確な座標を測ってから撮る | 数cm〜十数cm | 事前に現地へ入って設置・測量が必要 |
| **RTK / PPK ドローン** … 機体が自分の位置をcm級で知る | 数cm | 機材が要る。基準局か補正サービスが必要 |
| **後から平行移動で合わせる** … 現地でGNSSで1点測り、そのぶん全体をずらす | 数十cm〜1m | いちばん安い。既に撮ったオルソにも効く |

3つ目は今のデータにも使える。**全体が同じ方向に同じだけずれている**性質を利用して、
はっきり分かる目標物（道路の交差点、建物の角など）を1点だけ現地で測れば、
そのぶん全部をずらして合わせられる。

なお、いま撮ってあるオルソからは **後処理でこの補正はできない**
（撮影時の記録に元の情報が残っていないため）。現地での実測が要る。

## 8. 衛星画像の場合

衛星画像も考え方は同じだが、作られ方が違う。

衛星は斜めから撮るので、地形の起伏で像がゆがむ。これを
**オルソ補正（orthorectification）** で真上から見た形に直す。
このとき、衛星の姿勢を表す **RPC** という係数と、**標高データ（DEM）** を使う。

ここから、衛星画像の位置精度には2つの効き方がある。

1. **衛星の姿勢の精度** … 商用の高分解能衛星（WorldView等）で、GCPなしなら **CE90 で3〜5m程度**
2. **使ったDEMの精度** … DEMがずれていると、斜めから見ているぶんだけ横にずれる。
   急斜面ほど影響が大きい

結果として、**衛星画像の絶対精度もドローンオルソと同じくらい（数メートル）**になる。

そして重要なのは、**ドローンオルソと衛星画像は、それぞれ別の方向にずれている**ということ。
2つを重ねると、両者の間に数メートルの食い違いが見える。
これは「どちらかが壊れている」のではなく、**両方に数メートルの幅がある**というだけ。

同じ木を追いかけるときは、
**画像をまたいで座標で突き合わせるのではなく、画像の上で目で見て対応づける**ほうが確実。

---

## 9. まとめ

- 画像は「左上の座標」と「画素の大きさ」だけで地面に貼られている
- 変換の計算はミリ以下の精度で、ソフトは誤差を足していない
- **オルソの中は正確。地球上のどこかは ±3〜5m ずれる**
- ずれは全体が同じ方向に平行移動する形で出る
- 森林簿の側にも同じくらいの幅がある
- 精度を上げたいならGCPかRTK。既存データなら現地1点の実測で寄せられる
- 衛星画像も事情は同じで、ドローンとは別方向にずれる
