## 1. ナラ枯れという問題

ナラ枯れは、**カシノナガキクイムシ**（以下カシナガ）が媒介する**ナラ菌**によって
ミズナラ・コナラ・カシワなどのナラ類が集団的に枯死する被害である。
本州では長く問題になってきたが、北海道では長らく発生していなかった。

### 北海道での経過

| 時期 | できごと |
|---|---|
| 令和5年(2023)10月 | **道南で北海道初の被害を確認** |
| 令和6年(2024) | 渡島半島南端部を中心に被害継続 |
| 令和7年度(2025) | **道内11市町で2,001本**の被害木を確認。前季比7.7倍の急増局面 |
| 令和8年度(2026) | カシナガ生息調査で9市町464匹を確認 |

被害は津軽半島の対岸にあたる**渡島半島南端部から北へ**広がってきている。
北海道では本州と異なり、**幹の直径30cm未満の細い木でも枯死**し、
**穿入孔が少なくても枯死に至る**例が確認されている。

### 森町の位置づけ

森町は渡島管内の北寄りにあり、**被害の最前線が 北上してくる側**にある。

- **令和8年(2026)5月13日、森町砂原2丁目の町有林 1020林班で被害木を確認**
- 対象のミズナラ1本を伐倒し、1m程度に玉切りしたうえで薬剤注入とビニール被覆を実施。伐根も同様に処理
- **標高200m以下の高リスク区域を重点管理地域として設定**し、天然林の更新伐を計画的に実施予定
- ナラ類の伐採・移動はカシナガを広げるおそれがあるため、自己判断で行わず町（農林課 01374-7-1086）へ相談することとされている
- 国の交付金を活用し、令和8〜10年度の3ヵ年でミズナラの洋酒樽事業に取り組む予定

つまり森町は「**まだ本格的な被害には至っていないが、確実に来ている**」段階にある。
この段階で最も価値があるのは、**早期発見**と**発見から処理までの取りこぼしを無くすこと**である。

出典:
- 北海道水産林務部林務局森林整備課「ナラ枯れ被害について」 https://www.pref.hokkaido.lg.jp/sr/srs/new23/206717.html
- 森町「ナラ枯れ被害の防止と森町産ミズナラ資源の活用について」 https://www.town.hokkaido-mori.lg.jp/soshiki/norin/4319.html

## 2. 林務行政の年間サイクルと、詰まる場所

北海道が示している防除の流れは次のとおり。

| 時期 | やること |
|---|---|
| 7月頃 | カシナガの生息調査 |
| 8月・11月 | 被害監視区域の設定 |
| 9月頃 | **ヘリコプター等による上空調査** |
| 9月・10月 | **現地調査で被害判定** |
| 翌年5月末まで | 伐倒後焼却／伐倒後チップ化・焼却／伐倒くん蒸／立木くん蒸 |

このサイクルで実務が詰まるのは、次の3か所である。

### 詰まりどころ1：上空調査が高い・回数が限られる

ヘリコプターは費用も段取りも重く、年に何度も飛ばせない。
撮った映像から候補地点を拾う作業も目視で、担当者の負担が大きい。

→ **ドローンのオルソに置き換える。** 企画提案書の主眼もここにある。

### 詰まりどころ2：候補が出ても、どれから見に行くか決められない

上空から「茶色い樹冠」を拾うと、道路・裸地・自然枯れ・針葉樹の被害・
撮影時期の差など、ナラ枯れでないものが大量に混じる。
限られた人員で全部を見に行くことはできない。

→ **色だけで決めず、森林簿の樹種と標高を必ず併せて優先度を出す。**
これがこのビューアーの設計上いちばん重要な判断である（後述）。

### 詰まりどころ3：見た結果が散らばって、翌年に残らない

現地の記録が紙・Excel・写真フォルダ・個人の記憶に分かれる。
「あの木は見たのか」「なぜ違うと判断したのか」が翌年たどれない。
到達できなかった木は、そもそも記録に残らないことが多い。

→ **候補木1本ごとに、ステータス・結果・誤判別要因・写真・変更履歴を1か所に束ねる。**
「到達できず」を独立したステータスとして持たせているのはこのため。

### 詰まりどころ4：そもそも現地に行けない

これが実際にはいちばん大きい。渡島総合振興局が整理した森町の現地確認結果
（本ビューアーに「現地確認記録」として収録）を見ると、確認しようとした11地点のうち

- **5地点が到達不能**（笹薮1.5km以上／高低差100mの急斜面／熊の足跡で安全確保できず 等）
- ナラ枯れと確認できたのは **1地点だけ**（1020-2、燻蒸処理済み）
- 残る5地点は **ナラ枯れではなかった**（根むくれ2、つる植物1、原因不明2）

到達できない理由は現場では動かせない。人員を増やしても解決しない。

→ **ここがドローンの本丸である。** 実際、到達不能だった5地点のうち
**4地点が今回のオルソの範囲に入っており**、上空から確認できる状態になった。

| 到達不能地点 | 理由 | 覆っているオルソ | オルソから拾えた候補 |
|---|---|---|---|
| 1007-50 | 笹薮を1.5km以上 | Site B | **139件（うち優先度高 23件）** |
| 3-130 | 高低差100mの急斜面 | Site A | 6件（うち高 2件） |
| 105-188 | 熊の足跡・道路から1.5km | Site C | 2件 |
| 105-146 | 熊の足跡・道路から3km | Site C | 0件 |
| 国有林 | 位置未特定 | なし | — |

105-146 の「0件」も成果である。**行かずに「枯死らしい樹冠は無い」と分かった**ということだから。

## 3. 優先度をどう決めたか

**色だけで優先度を決めてはいけない**、というのがこの設計の中心にある。

行政が本当に知りたいのは「赤い樹冠がある」ことではなく、
「**ナラ類がある場所で**」「**カシナガが越冬できる標高で**」枯れているか、である。
そこで3つを掛け合わせている。

### (1) 色 ＋ 周囲が生きた林冠であること

赤褐色に変色し（ExR が高い）、緑が失われ（VARI が低い）、
彩度が十分にあり（道路・裸地は彩度が低い）、暗すぎない（日陰でない）領域を拾う。

これに加えて **「周囲が生きた緑の林冠に囲まれているか」** を必ず見る。
枯れた木は森の中に立っている。農地・裸地・屋根・伐採跡は周囲も緑ではない。
この1条件が、色ベースの手法でいちばん効く誤検出対策になる。

さらに、細長い領域（道路・林道）と、外接矩形に対する充填率が低い領域を落とす。

### (2) 樹種 ― 森林調査簿から

北海道オープンデータの森林調査簿には、小班ごとの樹種コードが入っている。
カシナガの寄主となるナラ類は **62=コナラ / 63=カシワ / 64=ミズナラ**。
これを含む小班を「ナラ類確実」、
**98=天然林広葉樹 / 99=針広混交林** を「ナラ類の可能性あり」として扱う。

森町の実データでは:

- ナラ類確実 … **68小班・126.0 ha**
- ナラ類の可能性 … **5,158小班**

### (3) 標高 ― 森町自身の基準

森町は**標高200m以下**を重点管理地域としている。
カシナガの越冬・活動と標高の関係を踏まえた、町自身が決めた運用上の線である。
国土地理院の標高タイル（DEM10B・10mメッシュ）で小班重心と候補木の標高を引き、
この基準をそのまま優先度に反映している。

森町のナラ類のうち**標高200m以下は 33小班・77.4 ha**。
つまり、**町全体で最初に守るべき面積は 80ha 弱**まで絞り込める。
この数字が出せること自体が、この道具の一番の実務価値だと考えている。

### 実装

```
順位づけ点数 = 色スコア
             + 0.20  ナラ類確実
             + 0.08  ナラ類の可能性
             - 0.10  小班内だがナラ類でない
             - 0.25  民有林の小班の外（農地・宅地・道路・国有林など）
             + 0.08  標高200m以下
```

この点数で**サイト内を順位づけし、上位40件を「高」、次の120件を「中」**、残りを「低」とする。
絶対的なしきい値にしていないのは、次の理由による。

実際に3サイトのオルソで試すと、絶対しきい値では Site A の487候補のうち
**407件が「高」**になってしまった。オルソの色味は撮影条件で大きく変わるため、
同じ数値が別のオルソでは別の意味になる。それよりも
**「このサイトで最初に見に行くべき40本」を必ず出せること**を優先した。

そもそも振興局の現地確認では、確認できた6地点のうち実際にナラ枯れだったのは1地点だけだった。
**色による抽出は診断ではなく順位づけ**である。現地確認の順番を決めるための道具として設計している。

件数は `--high-count` / `--mid-count` で変えられる。既定の40件は、
到達不能が多い現場で1シーズンに回れる現実的な本数として置いた。

民有林の小班の外にある候補を**消さずに「低」に落としている**のは、
森林調査簿が民有林しか収録していないためである。
実際、振興局の記録にも「国有林で小班なし」の地点がある。
国有林や、森林簿の更新前に変化した場所を機械的に切り捨てると、
本物の被害を取りこぼす危険がある。判断は人に残す。

## 4. 技術的な選択

### なぜローカルで動かすのか

- 現地は圏外のことがある。ノートPCを持ち込んでそのまま使えることが要る
- 位置情報は「被害木の位置情報として慎重に管理」する対象（企画提案書 10-4）。外に出さない
- 予算のかかるサーバーを前提にすると、実証が終わった時点で止まる
- 企画提案書 11-3 の方針「最初から大規模な専用システムを構築しない。道が運用しやすい最小構成から始める」に沿う

### なぜ外部ライブラリをほとんど使わないのか

**ビューアー本体（server.py）はPythonの標準ライブラリだけで動く。**
GDAL も Flask も Django も要らない。

行政のPCに何かをインストールするのは、それ自体が高い壁になる。
5年後に誰かがこのフォルダを開いたとき、`pip install` が通らなくて動かない、
という事態を避けたい。

オルソの取り込みだけは Pillow と numpy が要るが、これは年に数回の作業であり、
その2つは最も入れやすいライブラリでもある。

GDAL を使わずに済ませるために、次を自前で実装している:

| 機能 | 実装 | 場所 |
|---|---|---|
| 平面直角座標系XI系 ⇄ 緯度経度 | Krüger級数6次 | `tools/geo.py` |
| Shapefile(.shp/.shx/.dbf) の読み込み | バイナリ直読み | `tools/shapelib.py` |
| xlsx の読み込み | zip + XML | `tools/shapelib.py` |
| GeoTIFF の位置情報読み取り | IFDタグ直読み | `tools/ortho.py` |
| Webメルカトルへのタイル化 | タイルごとに9×9の制御格子で厳密変換し双一次補間 | `tools/ortho.py` |
| 連結成分ラベリング | scipy があれば使い、無ければ Union-Find | `tools/detect.py` |

投影計算は引き継ぎ資料に載っていた実測値と照合し、**誤差7cm以内**（資料側の記載桁数の限界）
であることを確認している。`py -3 tools/geo.py` を実行すると検証結果が出る。

### 座標系がそろっていること

| データ | 座標系 | 投影パラメータ |
|---|---|---|
| ドローンオルソ・DSM・点群 | EPSG:6679（JGD2011 XI系） | lat_0=44, lon_0=140.25, k=0.9999, GRS80 |
| 北海道の林班・小班shp | EPSG:2459（JGD2000 XI系） | **同上** |

投影法・原点・縮尺係数がまったく同じで、北海道では JGD2000 と JGD2011 の差は
数ミリ〜数センチしかない。よって**同一グリッドとして直接重ねられる**。
オルソの絶対位置誤差（±3〜5m）に比べれば無視できる。

### データベースを2つに分けている理由

| ファイル | 中身 | 再生成 |
|---|---|---|
| `data/survey.db` | **人が入力したもの**（調査結果・写真・履歴） | **できない** |
| `data/forest.db` | 北海道オープンデータから作った参照データ | できる |

引き継ぐ相手に「**これだけは消すな**」と1つのファイル名で言えることを優先した。
オルソを何度入れ直しても survey.db には触らない設計にしてある。

## 5. 企画提案書との対応

| 提案書の要件（11-2 ナラ枯れ検出の機能要件） | 実装 |
|---|---|
| AIが抽出した候補地点を地図上に表示、高・中・低の優先度で色分け | ○ 丸の大きさで優先度、色でステータス |
| 候補木ID、位置情報、メモ、最終確認日、要確認・現地確認済・判定保留等のステータス管理 | ○ さらに「到達できず」「処理済」を追加 |
| 写真、樹種、葉の変色、枯死状況、周辺林相、判定結果を記録し再学習用データ候補として整理 | ○ 誤判別要因も選択式で記録し、CSV/GeoJSONで書き出せる |
| レイヤーを指定して表示項目を絞り込める | ○ 林班界・小班界・ナラ類・標高200m以下 |
| GeoPackage、shp、GeoTIFF、CSV等で出力 | △ CSV / GeoJSON に対応。GeoJSONはQGISでshp/GeoPackageへ変換可 |
| 一般的なログイン/アカウント作成/権限付与 | × ローカル単独運用のため未実装。担当者名の記録と変更履歴で代替 |
| フィルターを用いて過年度のデータを参照 | △ サイト（オルソ）単位で年次を分けられる。年次比較の画面は未実装 |

未実装の2つは、いずれも**単独PCで動かす**という前提から外したもの。
複数人・複数年での本格運用に移る段階で、サーバー版として作るのが素直だと考えている。
（提案書 11-3 の「2027年度以降」に相当）

## 6. この先やるとよいこと

1. **AIモデルへの差し替え**
   `tools/detect.py` の `detect_candidates()` だけを差し替えれば済む形にしてある。
   現地調査の結果（特に「被害なし」＋誤判別要因）が教師データになる。

2. **年次比較**
   同じ範囲を毎年撮れば、サイトを年ごとに分けて登録できる。
   前年の候補木との差分を出す画面を足すと、拡大速度が見える。

3. **国有林データの追加**
   いまの森林簿は民有林のみ。国有林の林小班データを足せば、
   小班外として「低」に落ちている候補の一部が正しく評価される。

4. **GNSS実測値の取り込み**
   現地でGNSSを使って測った座標を入れられるようにすると、
   オルソの系統的なずれ（±3〜5m）を後から補正できる可能性がある。

5. **樹高の精度向上**
   いまの樹高はドローンDSMから国土地理院DEMを引いた参考値。
   航空レーザ測量成果（北海道が保有）のDTMがあれば、実用精度になる。
