# 外から使う（クラウド・遠隔アクセス）

事務所の外から、あるいは現地からこのビューアーを使いたいときの選び方。

---

## 先に、いちばん大事なこと

このデータには **被害木の位置、所有者確認のメモ（連絡先を書ける）、現地写真** が入る。
企画提案書 10-4 のとおり、取り扱いに注意が要るものである。

**公開URLに置くと、それが世界中から見える。** 絶対にやってはいけない。

いまのサーバーには**合言葉**が入っている（`tools/auth.py`）。
`--host` をループバック以外にすると自動で要求される。
ただし合言葉は「1つをチームで共有」する仕組みなので、**それ一枚に頼らない**。
**「そもそも到達できない」層を前に置く**のが基本。

---

## 選び方

| 方法 | 費用 | 公開されるか | 記録が消えないか | 向き |
|---|---|---|---|---|
| **Tailscale** | 無料 | **されない** | 消えない（事務所PCのまま） | **◎ 本命** |
| **Cloudflare Tunnel ＋ Access** | 無料 | Accessで守れば守れる | 消えない | ○ URLで渡したいとき |
| Render / Railway / Fly.io の無料枠 | 無料 | される | **✕ 再起動で記録が消える** | ✕ |
| VPS（Lightsail・さくら・ConoHa 等） | 数百円〜/月 | 設定次第 | 消えない | ○ 本格運用 |
| GitHub Pages | 無料 | **必ず公開** | — | ✕（そもそも動かない） |
| ギガファイル便などの転送サービス | 無料 | **される** | — | ✕ |

### 無料枠の PaaS が「✕」な理由

Render や Railway の無料枠は、**ディスクが揮発する**。
コンテナが再起動すると `data/survey.db` が初期状態に戻る。
このシステムでいちばん失ってはいけないものが、いちばん静かに消える。
有料の永続ディスクを付ければ使えるが、それなら VPS のほうが安い。

### GitHub Pages が「✕」な理由

1. 静的ファイルしか置けない。`server.py` が動かないので、林班を引くことも記録することもできない。
2. 無料枠の Pages は必ず公開になる。被害木の位置情報を全世界に出すことになる。

---

## 方法A：Tailscale（推奨）

事務所PCとスマホを、同じ**私設のネットワーク**に入れる。
インターネットには一切出さないまま、外から事務所PCに届くようになる。

### 手順

1. **事務所PCに Tailscale を入れる**（https://tailscale.com/download）
   個人利用は無料。アカウントは Google などで作れる。
2. **スマホにも入れて、同じアカウントでログインする。**
3. 事務所PCで、Tailscale の画面に出ている **100. で始まるIPアドレス**を控える
   （コマンドなら `tailscale ip -4`）。
4. 事務所PCでサーバーを、そのIPに向けて起動する。

   ```
   python server.py --host 100.x.y.z --no-browser
   ```

   ループバック以外なので、**合言葉が自動で要求される**。
   起動時の黒い画面に合言葉が出るので、使う人に伝える。

5. スマホの Tailscale を「接続」にして、ブラウザで
   `http://100.x.y.z:8765/` を開く。合言葉を1回入れれば、以後は素通り。

### 注意

- **事務所PCの電源を入れたままにしておく必要がある。** スリープすると切れる。
  電源オプションでスリープを「なし」にしておくこと。
- 初回は Windows のファイアウォールが確認を出す。**「プライベート ネットワーク」で許可**する。
- `--host 0.0.0.0` でも動くが、それだと**庁内LANの誰からも見える**。
  Tailscale のIPを指定するほうが範囲が狭くて安全。

### なぜこれが本命か

- 公開URLが存在しない。検索にもかからない。
- 追加費用ゼロ。
- 記録は事務所PCに残ったまま。バックアップの考え方が変わらない。
- 使わなくなったらアプリを消すだけで元に戻る。

## 方法B：Cloudflare Tunnel ＋ Access

「URLを渡して開いてもらう」形にしたいとき。

1. 事務所PCで `cloudflared` を動かし、`http://localhost:8765` を外に出す。
2. **必ず Cloudflare Access を併用する。**
   無料枠で、指定したメールアドレスの人だけに絞れる。

> **`cloudflared tunnel --url http://localhost:8765` だけで終わらせないこと。**
> あの1行で出る `*.trycloudflare.com` の URL は、**誰でも開ける**。
> 被害木の位置情報と現地写真がそこにある。
> 試すときも、必ずデータを空にした見本
> （`python tools/make_package.py --sample` で作れる）で試すこと。

Tailscale と比べると、設定する箇所が多く、間違えたときの被害が大きい。
**役場の中で使うだけなら Tailscale を勧める。**

---

## 方法C：VPS を借りる

来年以降も複数人で常用する、事務所PCを開けっぱなしにできない、という段階になったら。

- Lightsail / さくらのVPS / ConoHa で月 数百円〜
- 永続ディスクがあるので記録が消えない
- 前段に Basic 認証か Cloudflare Access を置く
- **バックアップの担当と手順を決め直すこと**（`バックアップ.bat` は手元前提）

自治体の情報セキュリティポリシー上、外部サーバーに業務データを置けるかは
**必ず担当課に確認**すること。ここは技術ではなく手続きの問題。

---

## いますぐ「見せるだけ」でよいなら

書き込みは要らず、状況を共有したいだけなら、**控えのページを作って渡す**のがいちばん軽い。
地図タイルは付かないが、記録・座標・進捗・期限は入る。

作り方は担当者に頼むか、`python tools/backup.py` で控えを取ってから
CSV（`/api/export.csv`）を渡すのでも足りることが多い。

---

## まとめ

1. **公開URLに置かない。** これだけは動かせない。
2. 外から使うなら **Tailscale**。無料で、公開されず、記録は事務所PCのまま。
3. 合言葉は「そもそも到達できない」層の**補助**であって、代わりではない。
4. 外部サーバーに置くなら、技術の前に**担当課への確認**。
