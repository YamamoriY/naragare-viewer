# ナラ枯れビューアー 運用マニュアル

北海道茅部郡森町／令和8年度

---

## 1. これは何をする道具か

ドローンのオルソ画像の上で、ナラ枯れが疑われる木を
**記録し、現地確認の結果を残し、処理の期限を管理する**ための道具です。

紙とExcelでやっていたことを、地図の上で一本化します。

| 従来 | このビューアー |
|---|---|
| ヘリコプターで上空から目視 | ドローンのオルソを画面上で確認できる |
| 現地に入れず確認できない | **人が到達できない場所も上空から見られる** |
| Excelの一覧と紙地図を突き合わせる | 地図と一覧が同じ画面。クリックで行き来 |
| 林班番号を図面から手で拾う | 森林簿から自動で林班・小班・樹種・地番を付与 |
| 座標を図面から読み取る | 緯度経度・度分秒・平面直角XI系をその場でコピー |
| 処理期限を頭で管理 | 5月末までの残り日数と未処理件数を常時表示 |

なお **候補木の自動抽出は行いません**。抽出は別のアルゴリズムで行い、
後からこのデータベースにマージする前提です（11章）。

## 2. 画面の見方

### 上のタブ

| タブ | 中身 |
|---|---|
| **地図** | 候補木を地図に表示。クリックすると右に詳細が開く |
| **一覧** | 表形式。並び替えできる。行をクリックすると地図に飛ぶ |
| **進捗** | 林班ごとの調査の進み具合、処理期限、次にやること |
| **データについて** | 出典・精度・優先度の決め方 |

### 左の列

- **サイト（オルソ）** … オルソ1枚ぶんの範囲。切り替えるとその範囲に飛ぶ
- **絞り込み** … ステータス・優先度・林班・キーワード
- **重ねる情報** … 林班界、小班界、ナラ類の小班、標高200m以下の区域
- **凡例** … 丸の色＝ステータス、丸の大きさ＝優先度
- **書き出し** … 絞り込んだ内容をそのままCSV／GeoJSONで出力

### 右の詳細

候補木をクリックすると開きます。ここで現地調査の結果を記録します。

## 3. 現地調査の記録のしかた

### 3-1. 事前準備（事務所で）

1. **担当者名を入れる**（画面右上）
   　変更履歴に残ります。誰がいつ何を変えたか後から追えます。
2. **優先度「高」で絞り込む**
   　左の「優先度」で「高」をクリック。
3. **CSVで書き出して印刷する／タブレットに入れる**
   　「CSV（Excel）」を押すと、いま絞り込んでいる木だけが出ます。
   　緯度経度・林班・小班・地番が入っているので、そのまま現地で使えます。

### 3-2. 現地で

木を見つけたら、その木の詳細を開いて **ステータス** を押します。

| ステータス | どんなとき |
|---|---|
| **未調査** | まだ見に行っていない（初期値） |
| **現地調査済・被害あり** | ナラ枯れだった。処理が必要 |
| **現地調査済・被害なし** | 見に行ったが、ナラ枯れではなかった（誤検出） |
| **判定保留** | 見たが判断がつかない。再確認が必要 |
| **到達できず** | 現地に近づけなかった |
| **処理済** | 伐倒くん蒸などの処理が終わった |

**「到達できず」にしたときは、必ず「到達状況・アクセスの記録」に理由を書いてください。**
「沢を渡れず接近不可、対岸から目視」のように書いておくと、
次の人が同じ失敗を繰り返さずに済みます。

**「現地調査済・被害なし」にしたときは、「誤判別だった場合の要因」を選んでください。**
自然枯れ／影・地形／道路・裸地 などを選んでおくと、
翌年のAIモデルの精度改善にそのまま使えます。ここが将来の財産になります。

### 3-3. 記録する項目

企画提案書 9-1 のプロット調査項目に対応しています。

- 樹種、胸高直径
- 葉の変色、枯死状況、穿孔（カシナガ）、フラス量
- 周辺林相
- 写真（樹冠・葉・幹・周辺林相）… ドラッグ＆ドロップで貼れます

最後に **「保存」** を押してください。ステータスだけは押した時点で即保存されます。

### 3-4. 木を新しく登録する

地図の右側の **📍 木を登録**（キー `A`）を押してから、
オルソの上で木のある場所をタップします。
林班・小班・樹種・代表地番・標高は森林簿から自動で入ります。

位置がずれていたら、詳細画面の「**ピンを動かして直す**」でドラッグして直せます（10章）。

## 4. 処理の期限管理

被害が確認された木は、**カシノナガキクイムシが脱出する翌年5月末まで**に
処理を終える必要があります。

処理方法（北海道の被害木処理の手引による4方法）:

- 伐倒後焼却
- 伐倒後チップ化・焼却
- 伐倒くん蒸
- 立木くん蒸

画面右上に **残り日数** が常に出ています。
「進捗」タブに、いま「被害あり」で未処理の本数が出ます。
処理が終わったらステータスを **「処理済」** にし、処理方法と処理日を入れてください。

## 5. 新しいオルソを入れる

### 手順A：画面から（おすすめ）

1. 右上の **「＋ オルソを取り込む」**（キー `I`）
2. **「参照…」** でファイルを選ぶ
   　ドライブをたどって選べます。位置情報の有無・DSMの有無・容量が出ます
3. サイトID・撮影日・名前を入れて **「取り込みを始める」**

進み具合が画面に出ます。途中で閉じても取り込みは続きます。
うまくいかなかったときは `data/_import.log` に記録が残ります。

### 手順B：フォルダにまとめて置く

1. `オルソ投入` フォルダに置く

   ```
   オルソ投入/
     siteA_ortho.tif          ← GeoTIFF（推奨。アルファ付き）
     siteA_dsm.tif            ← あれば樹高の参考値が出る
   ```

   または

   ```
   オルソ投入/
     siteA_ortho.jpg
     siteA_ortho.jgw          ← ワールドファイル。必須
   ```

2. `オルソを取り込む.bat` をダブルクリック
3. 終わったら `起動.bat`

### 何が起きるか

1. オルソの位置情報を読む（GeoTIFFのタグ、またはワールドファイル）
2. Webメルカトルの地図タイルに変換して `data/tiles/<サイト名>/` に書く
3. サイトとして `data/survey.db` に登録する

**候補木は作りません。** 作りたい場合は 11章 を参照してください。

### すでに入力した記録はどうなるか

**消えません。** 同じサイトで前回と同じ場所（既定 3m 以内）にある木は
同一の木とみなし、**人が入力した項目（ステータス・調査日・写真・メモなど）は
一切上書きしません。** 検出スコアや優先度だけが新しい値に更新されます。

今回検出されなかった既存の木も削除されません（そのまま残ります）。

### 同梱の色ベース抽出を使うときの調整

（`--detect` を付けたときだけ関係します。通常は読み飛ばして構いません）

オルソの色味は撮影条件で変わります。既定値で合わないときは調整できます。

```
オルソを取り込む.bat "オルソ投入\siteA_ortho.tif" --dry-run
```

`--dry-run` を付けるとデータベースに書かずに結果だけ表示します。
件数を見ながら次のつまみを動かしてください。

| つまみ | 意味 | 候補を増やすには |
|---|---|---|
| `--exr-min` | 赤みの下限（既定 0.02） | 小さく |
| `--vari-max` | 緑らしさの上限（既定 0.02） | 大きく |
| `--sat-min` | 彩度の下限（既定 0.18）。道路・裸地を落とす | 小さく |
| `--val-min` | 明るさの下限（既定 0.22）。日陰を落とす | 小さく |
| `--min-area` `--max-area` | 樹冠の面積 m²（既定 2〜400） | 範囲を広げる |
| `--limit` | 登録する上限件数（既定 3000） | 大きく |
| `--high-count` | 優先度「高」にする件数（既定 40） | 大きく |
| `--mid-count` | 優先度「中」にする件数（既定 120） | 大きく |

優先度は**サイトごとの相対順位**で決まります。候補が何件あっても、
上位40件が「高」、次の120件が「中」になります。
1シーズンに回れる本数に合わせて `--high-count` を変えてください。

例）候補が少なすぎるとき:

```
オルソを取り込む.bat "オルソ投入\siteA_ortho.tif" --exr-min 0.01 --vari-max 0.05 --dry-run
```

納得できたら `--dry-run` を外して実行します。

### オルソを差し替えるとき

同じサイト名で取り込み直せば上書きされます（調査記録は保持）。
サイトごと消したいときは:

```
py -3 tools\remove_site.py                  一覧を見る
py -3 tools\remove_site.py siteA            削除（調査記録があれば中止される）
py -3 tools\remove_site.py siteA --force    調査記録ごと削除
```

## 6. 書き出し

| 形式 | 用途 |
|---|---|
| **CSV（Excel）** | 現地持参用の一覧、報告書の別表、集計。UTF-8 BOM付きなのでExcelでそのまま開けます |
| **GeoJSON（QGIS）** | QGIS等のGISソフトで開く。他システムへの受け渡し |

いま画面で絞り込んでいる条件がそのまま反映されます。
サイト・ステータス・優先度・林班・キーワードで絞ってから押してください。

QGISで開くときの座標系は **EPSG:4326（WGS84）** です。
平面直角座標系XI系の値（東距・北距）もCSVの列に入っています。

## 8. よくある質問

**Q. 何人かで同時に使えますか**
A. 1台のPCで1人ずつ使う前提です。複数人で同時に使いたい場合は、
1台をサーバー役にして `py -3 server.py --host 0.0.0.0` で起動すれば
同じネットワークの他のPCからブラウザで開けます。
ただしログイン機能は無いので、庁内LANなど信頼できるネットワーク内に限ってください。

**Q. 座標がずれて見えます**
A. オルソの絶対位置に水平±3〜5mの誤差があります（GCP・RTK未使用）。仕様です。
「データについて」タブに詳しく書いてあります。

**Q. 現地は圏外です**
A. `初期設定.bat` で背景地図をローカルに取り込んであれば、
インターネットが無くても地図は表示されます。
ノートPCを持ち込んで `起動.bat` を実行すれば現地でそのまま使えます。

**Q. 樹高が出ません**
A. DSM（`<サイト名>_dsm.tif`）が必要です。
出てくる値は国土地理院の地表面標高との差分で、**あくまで参考値**です。
DSMの高さ自体が気圧高度由来の誤差を含むため、目安としてのみお使いください。

**Q. AIモデルができたら差し替えられますか**
A. `tools/detect.py` の `detect_candidates()` を差し替えるだけで済むように作ってあります。
戻り値の形（x, y, area_m2, score …）を合わせれば、他は変更不要です。

**Q. 森町以外でも使えますか**
A. `tools/build_forest.py` の `MORI = '15'` を対象市町村のコードに変え、
必要なら振興局の zip URL を変えれば動きます。
コード表は `data/_src/oshima/森林調査簿コード.xlsx` にあります。

## 10. 木の位置をきちんと出す・直す

木を選ぶと、右側に **位置** の欄が出ます。

| 表示 | 例 |
|---|---|
| 緯度経度（10進・小数7桁） | `42.1059958, 140.6834744` |
| 度分秒 | `42°06′21.59″N 140°41′00.51″E` |
| 平面直角座標系XI系 [m] | `X -210302.73  Y 35850.30` |
| 標高（国土地理院DEM10B） | `156.9 m（重点管理）` |

それぞれ右の **⧉** で コピーできます。GPSやカーナビに貼れます。
**地理院地図／Googleマップ／経路** のボタンから、その地点を外部の地図で開けます。

> **平面直角座標の X と Y**
> 日本の平面直角座標系では **X が北向き、Y が東向き**です（数学のグラフと逆）。
> 森町は原点（北緯44度・東経140度15分）より南なので、X はいつも大きな負の数
> （−205,000〜−215,000 くらい）、Y は +14,000〜+40,000 くらいになります。
> 国土地理院の座標変換やジオグラフィカと同じ並びなので、そのまま貼り付けられます。

### 位置を直す（緯度経度を入れる）

GPS機やジオグラフィカで測った座標があるなら、詳細画面の
「**緯度経度を入れて直す**」の欄に貼って「**この座標にする**」を押します。
何メートル動くかを確認する画面が出ます。

受け付ける書き方（どれでもそのまま貼れます）

| 書き方 | 例 |
|---|---|
| 10進の度 | `42.105986, 140.683474` |
| 度分秒（記号が前） | `N42°06'21.5" E140°41'00.5"` |
| 度分秒（記号が後ろ） | `42°06'21.5"N, 140°41'00.5"E` |
| 度分 | `N42°06.358' E140°41.008'` |
| 漢字 | `北緯42度6分21.5秒 東経140度41分0.5秒` |
| 平面直角XI系 | `X=-209542.46 Y=37167.87` |

全角で書かれていても読みます。森町から大きく離れた場所になったときは
赤字で注意が出るので、書き方の間違いに気づけます。

> ### いちばんやりがちな間違い：記号を外して書く
>
> GPS機やジオグラフィカの画面には **`42°06'27.33"`** のように出ます。
> これを記号だけ外して **`42.062733`** と書くと、**まったく別の場所**になります。
>
> | 書き方 | 実際に指す場所 |
> |---|---|
> | `42.062733, 140.410217`（10進として読まれる） | 森町の西のはずれ |
> | `42°06'27.33"N 140°41'02.17"E`（本来の意味） | 更新伐R8のあたり |
> | **二つの距離** | **23.1 km** |
>
> やっかいなのは、**間違えたほうも森町の中に落ちる**ことです。
> 地図を見ても「まあこのへんかな」と見えてしまい、気づけません。
>
> **記号ごとそのまま貼り付けてください。**
> 手で打ち直すなら、10進の度に直してから入れてください
> （度 ＋ 分÷60 ＋ 秒÷3600）。
>
> この間違いをすると、画面に橙色で
> 「もしかして度分秒（42°06′27.33″N 140°41′02.17″E）ですか？」と出て、
> 「**度分秒として読み直す**」で直せます。
> ただし**両方の読み方がどちらも森町に入るときだけ**出るので、
> 出なかったから正しい、とは限りません。

> **度分秒で貼るときの注意**
> GPS機やジオグラフィカの度分秒表示は 0.1秒（緯度で約3m）までしか出ません。
> 度分表示なら 0.001分（約2m）です。
> **正確に合わせたいときは10進の度（小数6桁以上）を使ってください。**
> 「入れた座標と少し違う場所にピンが立つ」のは、たいていこれが原因です。

### 位置を直す（オルソ上で微調整）

**どの記録でも**、詳細画面の「**オルソ上で位置を直す**」から直せます。

押すと、オルソが自動で表示され、ズーム20まで寄ります。
そこで **ピンをドラッグ**するか、**地図をタップ**すると、その場所へ動きます。
動かしている間、画面上部に

- いまの緯度経度
- **元の位置から何メートル動かしたか**

が出て、元の位置とは黄色い破線で結ばれます。
納得したら「**この位置で確定**」、やめるなら「やめる（Esc）」。

確定すると、平面直角座標・林班・小班・樹種・代表地番・標高がすべて引き直され、
「位置の確からしさ」が **「オルソ上で目視により特定」** に変わります。

#### なぜこれが要るか

振興局・町から引き継いだ11件の記録は、**小班の代表点（重心）**に置いてあります。
公表されているのが林班-小班までで、木そのものの座標は無いからです。

**これは木の座標ではありません。**小班はひとつの区画なので広さがあり、
森町の該当小班では代表点から小班の縁まで **51m〜489m** あります。
つまり木そのものは、地図上の点から**数百メートル離れていることがあります**。
オルソの位置ずれ（1〜7m）より二桁大きい、いちばん大きな「ずれ」です。

そういう記録を開くと、位置の欄に橙色の注意書きが出ます。

> この位置は木の座標ではありません。1020林班-2小班（5.27 ha）の代表点（重心）です。
> **木は、この点から最大 254.6 m 離れている可能性があります。**

「**小班の範囲を地図に出す**」を押すと小班の輪郭が描かれ、
木がどの範囲のどこかにあるのかが目で分かります。

オルソを見て枯れている木が特定できたら、この機能でその位置に直してください。
**「小班のどこか」から「この木」に精度が上がります。**
直すと注意書きは消えます。**この作業が、この道具でいちばん価値のある仕事です。**

#### 元に戻せます

一度でも動かすと、**登録時の位置が控えとして残り**、「元に戻す」ボタンが出ます。
押せば座標も林班・小班・標高も、位置の確からしさの文言も、すべて元通りになります。

地図上では、位置を調整した木は **金色の縁**で表示され、
マウスを乗せると「位置を調整済み」と出ます。
どれが代表点のままで、どれが実際の木の位置か、ひと目で分かります。

現地でGNSSを使って正確な座標が分かったときも、この方法で直せます。

## 11. 候補木の自動抽出について

**オルソを取り込んでも、候補木は自動では作られません。**
抽出は別のアルゴリズムで行い、後からこのデータベースにマージする前提です。

同梱の色ベース抽出（企画提案書 7-1 のデモと同じ考え方）を試したい場合は、
取り込み画面で「同梱の色ベース抽出で候補木も作る」にチェックを入れてください。
コマンドからは `--detect` を付けます。

作った候補木をあとで消したいときは:

```
py -3 tools\purge_candidates.py --dry-run   件数だけ見る
py -3 tools\purge_candidates.py             調査記録があるものは残して消す
py -3 tools\purge_candidates.py --all       全部消す
```

外部で作った候補木を入れるときは、`data/survey.db` の `trees` テーブルに
`source` を独自の値（例 `'ai2'`）にして入れてください。
`purge_candidates.py --source ai2` でその分だけ消せます。
必須なのは `code`（一意）, `site`, `lon`, `lat` で、
`x/y/rinpan/kosyoban/elev` は `/api/locate?lon=&lat=` で引けます。

## 12. 現地写真をまとめて取り込む

スマートフォンで撮った写真には撮影地点の位置情報（GPS）が入っています。
それを読んで **どの木の写真かを自動で判別** します。

1. 画面右上の **「📷 現地写真」**（キー `P`）
2. その日撮った写真を**まとめて**ドロップ
3. 結果が出ます

| 結果 | 意味 |
|---|---|
| 既存の木の写真として追加 | 指定した距離（既定30m）以内に木があった。何m先だったかも出ます |
| 新しく登録した木 | 近くに木が無かったので、その場所に登録した。林班・小班・樹種・地番も自動で入ります |
| 位置情報が無い写真 | GPSがオフだった写真。木を選んでから個別に貼ってください |

**スマホのGPSは数m〜十数mの誤差があります。** 位置がずれていたら、
詳細画面の「ピンを動かして直す」で直せます。

写真を撮るときにスマホの位置情報をオンにしておくのがコツです。
これだけで、帰ってからの入力作業がほとんど無くなります。

## 13. まとめて直す（一括編集）

「一覧」タブで、行の左のチェックを入れて選びます。
上の **「選択」** で全部を選べます。

選ぶと青いバーが出るので、変えたい項目だけ入れて **「まとめて反映」**。

- ステータス
- 優先度
- 調査日
- 調査者
- 到達状況

**入れなかった項目は変わりません。** 変更は1件ずつ履歴に残ります。

「この小班の20本はまとめて到達できなかった」という記録が1操作で済みます。

## 14. 2枚の画像を見比べる

地図の右の **◧ 見比べ**（キー `C`）を押すと、2枚を左右に分けて表示します。
真ん中の黄色い線を **左右にドラッグ** すると、境目が動きます。

- 去年のオルソと今年のオルソ
- ドローンのオルソと衛星画像
- 同じ場所の別時期の衛星画像

被害がどう広がったかを見るのに使えます。
追加のデータは要りません（タイルはすでにあるので容量は増えません）。

## 15. 衛星画像を取り込む

**オルソと同じ入口**（「＋ 画像を取り込む」）から入れられます。

座標系は**自動で判定**します。

| 座標系 | 例 |
|---|---|
| 平面直角座標系 I〜XIX系 | ドローンのオルソ（XI系） |
| UTM 51N〜56N | 衛星画像で最も多い（北海道は54N） |
| 緯度経度 | EPSG:4326 / 6668 |
| Webメルカトル | EPSG:3857 |

判定は ①GeoTIFFのGeoKey ②`.prj`ファイル の順に見ます。
どちらも無い場合は平面直角座標系XI系として扱うので、違う場合は明示してください。

```
py -3 tools\ingest_ortho.py 衛星画像.tif --site sat2026 --epsg 32654
```

### 分解能によってできることが変わります

| 衛星 | 分解能 | 見えるもの |
|---|---|---|
| WorldView / GeoEye / Pleiades | 30〜50cm | 樹冠1本ずつ。個体の判別ができる |
| Sentinel-2（無償） | 10m | 木1本は見えない。「この小班が茶色い」という面の変化 |

**衛星画像はドローンのオルソと数メートルずれて見えます。**
どちらかが壊れているのではなく、両方に数mの幅があるためです。
詳しくは `docs/位置合わせと精度.md` を読んでください。
