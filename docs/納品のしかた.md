# 納品のしかた

役場に渡して、そのまま使ってもらうための手順。

---

## 1. まず作る

```
納品セットを作る.bat        をダブルクリック
```

または

```bash
python tools/make_package.py
```

`納品/ナラ枯れビューアー_一式_YYYYMMDD.zip` ができる。数分かかる。

> **OneDrive の中で作るときの注意**
> このプロジェクトは OneDrive の中にある。できあがった 350 MB の ZIP は
> **OneDrive が自動でアップロードしはじめる**。回線を長時間使うので、
> 気になるなら ZIP を OneDrive の外（デスクトップ直下ではなく `C:\納品` など）へ
> 移すか、`-o` で出力先を指定すること。
>
> ```bash
> python tools/make_package.py -o "C:\納品"
> ```
>
> 作業用の一時フォルダは OneDrive の外（Windows の一時フォルダ）に作るので、
> 2万5千個のファイルが同期されることはない。

| 作るもの | コマンド | 大きさの目安 | いつ使うか |
|---|---|---|---|
| **一式** | （引数なし） | 約 350 MB | はじめて渡すとき |
| **コードのみ** | `--update` | 約 15 MB | あとから直したものを届けるとき |
| **見本** | `--sample` | 約 90 MB | 調査記録を空にして外部に見せるとき |
| 軽い一式 | `--no-tiles` | 約 46 MB | オルソを見せなくてよいとき |

### 中身

```
ナラ枯れビューアー_一式_YYYYMMDD/
  はじめにお読みください.txt   ← 相手が最初に読む紙
  起動.bat                     ← ダブルクリックするだけ
  python/                      ← 埋め込み版Python + numpy + Pillow
  app/  tools/  docs/  server.py
  data/
    survey.db                  現地調査の記録
    photos/                    現地写真
    forest.db  layers/         林班・小班・森林調査簿
    tiles/                     オルソの地図タイル（いちばん大きい）
    basemap/  dem_cache/       背景地図と標高の控え
  オルソ投入/                   ← 新しいオルソを置く場所
```

### インストールが要らない理由

**Python をフォルダの中に同梱している。**

役場のPCは管理者権限が無くてソフトを入れられないことが多い。
そこで Python の「埋め込み版」（python.org が配っている、
フォルダに置くだけで動く版）を入れてある。

- インストール不要
- 管理者権限 不要
- レジストリを触らない、環境変数も変えない
- フォルダを消せば跡形もなく消える

Python は PSF ライセンスで再配布が認められている。`python/LICENSE.txt` も同梱される。

オルソの取り込みに要る numpy と Pillow も同梱してあるので、
**役場だけで新しいオルソを入れられる。**

## 2. どうやって渡すか

### 比較

| 方法 | 費用 | 上限 | 相手の準備 | 判断 |
|---|---|---|---|---|
| **USBメモリ / 外付けSSD** | 媒体代のみ | なし | なし | **◎ 第一候補** |
| **GitHub Release**（Privateリポジトリ） | 無料 | 2GB/ファイル | GitHubアカウント＋招待 | ○ 更新の配布向き |
| **OneDrive / Google Drive の共有リンク** | 無料 | 5GB / 15GB | ブラウザだけ | ○ 手軽。要パスワード＋期限 |
| ギガファイル便などの転送サービス | 無料 | 大 | なし | **✕ 使わない** |
| GitHub Pages で公開 | 無料 | — | ブラウザだけ | **✕ できない** |

### なぜ USB が第一候補か

- 自治体の庁内ネットワークは、外部サイトからのダウンロードが制限されていることが多い
- 350 MB を確実に渡せる
- **渡すデータに被害木の位置情報・所有者確認のメモ・現地写真が入る。**
  ネットワークを経由しないのがいちばん安全

ただし、**役場によってはUSBの持ち込み・接続が禁止**されている。
先に担当者へ確認すること。禁止ならOneDriveの共有リンクになる。

### なぜ GitHub Pages が使えないか

理由は2つ。どちらも致命的。

1. **Python のサーバーが動かない。** GitHub Pages は静的ファイルしか置けない。
   このビューアーは `server.py` が林班を引いたり記録を保存したりしている。
2. **無料枠の GitHub Pages は必ず公開になる。**
   被害木の位置情報を全世界に出すことになる。
   企画提案書 10-4 の趣旨にも反する。

「URLを開くだけで見せたい」なら、静的な閲覧専用版を別に作る必要がある。
その場合も、**公開してよいデータかを先に決めること。**

### ギガファイル便などを使わない理由

URLを知っていれば誰でも落とせる。被害木の位置情報と現地写真が入っているので使わない。

## 3. 渡すときに伝えること

### ZIPのブロックを解除してもらう

インターネット経由で受け取ったZIPは、Windowsがブロックすることがある。
**展開する前に**、ZIPを右クリック →「プロパティ」→ 下の方の
「セキュリティ: このファイルは他のコンピューターから取得したものです」の
**「許可する」にチェック** → OK。

これをしないと、中の `.bat` が動かないことがある。
（USBで渡した場合は起きない）

### 置き場所

**Cドライブなど、書き込みできる場所に展開してもらう。**
USBメモリのまま動かすと、地図の表示がとても遅くなる。

デスクトップやドキュメントの下でよい。ネットワークドライブは避ける。

### 最初の起動

`起動.bat` をダブルクリック → 黒い画面が出て、ブラウザが開く。
終わるときは黒い画面を閉じる。

外部と通信するのは、控えに無い範囲の地図タイルを国土地理院から
取りにいくときだけ。**記録が外に出ることはない。**

### ウイルス対策ソフトについて

`python.exe` を含むので、警告が出ることがある。
出たら、フォルダごと除外に追加してもらう。
心配なら、渡す前に自分のPCで一度動かして見せると早い。

## 4. データの扱い

渡すZIPには次のものが入る。**渡す相手を必ず確かめること。**

| 中身 | 注意 |
|---|---|
| 被害木の位置（緯度経度） | 企画提案書 10-4。取り扱い注意 |
| 所有者確認のメモ | 連絡先や経緯を書ける欄。個人情報が入りうる |
| 現地写真 | 人や車が写り込むことがある |

外部に見せるだけなら **`--sample`** を使う。
位置・林班・小班は残り、調査記録・写真・履歴・所有者メモが空になる。

```bash
python tools/make_package.py --sample
```

---

## 5. あとから直したものを届ける

```bash
python tools/make_package.py --update
```

コードと文書だけの約 15 MB。メールに添付できる大きさ。

相手には **「data フォルダと python フォルダはそのままにして、
上書きで展開してください」** と伝える。調査の記録は消えない。

同梱Pythonは入っていないので、相手のフォルダにある `python/` がそのまま使われる。

---

## 6. 渡したあとに必ず伝えること

> **`data\survey.db` と `data\photos\` は、そのPCにしかありません。**
> **月に一度、「バックアップ.bat」を実行してください。**

`ナラ枯れビューアー/バックアップ/日付_時刻/` に控えができる。
できれば別のPCか外付けの媒体にもコピーしてもらう。

これを伝えないと、PCの故障や入れ替えで現地調査の記録が全部消える。
**このシステムでいちばん失われやすいのは、コードではなく記録のほう。**

---

## 7. 外から使いたいと言われたら

`docs/外から使う.md` を読むこと。要点だけ。

- **公開URLに置かない。** 被害木の位置と現地写真が入っている。
- 外から使うなら **Tailscale**（無料・公開されない・記録は事務所PCのまま）。
- Render などの無料枠は、**再起動で調査記録が消える**ので使わない。
- 外部サーバーに業務データを置けるかは、技術の前に**担当課に確認**。

---

## 8. 試用のあと

うまくいったら、次に決めることは

1. **どのPCで運用するか**（1台に決めて、そこで記録する）
2. **誰がバックアップを取るか**（担当者を決める）
3. **来年のオルソをどう入れるか**（`オルソを取り込む.bat` の手順を一度一緒にやる）
4. 複数人・複数端末で使いたいか（別途、同期の仕組みが要る）

3 は必ず一度は一緒にやること。
**「オルソを入れれば成立する」ことを、実際にやって見せるまでが引き継ぎ。**
